# Croco Video Factory P1–P8 流程重构审阅草案

> 状态：用户已批准实施；正式运行权威为 Plugin 0.1.2 的 `SKILL.md` 与 references，本文保留为设计依据。
>
> 本文根据当前讨论重构从立项到正式 H3 分镜画面的流程；暂不把验收后的合片与交付纳入 P1–P8。Plugin 已按本文及迁移矩阵更新。

## 1. 总体目标

P1–P4 完成前期策划与前期设计资产，P5 将已定稿的文字分镜视觉化为 Storyboard，P6 锁定正式 H3 生成片段提示词，随后直接进入 P8 生成正式 H3 分镜画面。每段生成后由视频理解对照锁定剧本、P4 分镜规划和 P6 Prompt；不一致时只回 P6 拆分或扩展生成片段，不重做 P4 导演规划。P7 Trailer/Pre-roll 已取消。

推荐主流程：

```text
模式选择
  ↓
P1 项目需求与创作边界
  ↓
P2 主题分析 → 内容大纲 → Codex 调研/source verification/事实 Gate ↺ 内容大纲 → 剧本初稿 → GLM 去 AI 化 → 最终剧本
  ↓                                                        强制用户确认（Auto / 互动都停）
P3 角色需求 → 角色设定/Variation/音色/四视图 → 剧本场景与道具需求 → 每场景综合设定图
  ↓
P4 全片导演拍摄规则 → 根据剧本拆分文字分镜 → 预估生成时长 → 逐分镜导演设计 → 跨分镜审核与锁定
  ↓
P5 Storyboard 提示词 → Storyboard 生成 → Storyboard 验收与锁定
  ↓
P6 正式 H3 生成片段提示词 → 锁定
  ↓
P8 按 P6 提示词生成正式 H3 分镜画面 → 视频理解对照剧本/规划
  ↺ 不一致：只回 P6 延长、按场景切换/不连续边界拆分或增加延续片段
  ↓
一致性通过后停止：暂不 ASR、人工视觉验收、拼接或交付
```

## 2. 不变的模式原则

第一轮仍只确认两个维度：

1. 生产控制：`Auto` / `互动`；
2. 执行后端：`Canvas` / `Skill 原生`。

两组选择不改变阶段、产物或质量标准，只改变暂停方式和事实载体。

本次明确一个不受模式影响的强制人工门禁：

- **P2 最终剧本确认**：Auto 和互动模式都必须停。

其余阶段在互动模式下是否逐阶段暂停、Auto 模式如何记录自动通过，仍按后续确认的门禁政策执行。

## 3. Canvas 真实节点执行原则

所有 Canvas 已支持的文字、图像、视频生成都必须通过真实节点运行时完成。MCP 只负责创建、配置、连接、运行、查询状态、整理布局和标记当前有效结果，不得在 Canvas 外完成内容后直接写入一个结果节点。

### 3.1 需要外部文字模型时的节点链

不是每个 Text 产物都必须调用外部文字模型。字段整理、资源索引、确定性映射、固定模板组装、哈希、状态和 Gate 记录由 Codex / Script / MCP 原子能力完成。只有下文[模型调用矩阵](#33-旧流程模型落点与新流程调用矩阵)明确标为外部模型的关键创作/审核任务，才创建并运行对应 Text Config。

```text
上游 / 用户输入 Text
System Prompt Text
        ↓
指定外部文字模型 Text Config
        ↓
模型 Result Text
```

只有矩阵规定需要第二模型审核时，才在后面连接审核 Config。若人工反馈改变模型负责的创意方向，应重跑对应模型 Config 生成新 Result；MCP 不得直接编辑模型 Result 正文。由 Codex / Script 确定性形成的普通 Text 不是“模型 Result”，可以通过 canonical command 更新，但必须保留来源和版本。

### 3.2 图像链

```text
已锁定文字设定 Result + 已有 Reference Image
        ↓
Image Prompt Text Config（需要模型整理时）
        ↓
Image Prompt Result Text
        ↓
Image Config
        ↓
Image Result
        ↓
真实图像验收记录
```

研究和验证动作本身不创建“研究进度 Text Node”或“验证进度 Text Node”；但模型实际消费的研究结论必须成为输入 Text。Codex 调研 Gate 使用可追溯 Comment/metadata 保存结论；只有矩阵明确要求的外部模型审核意见才必须来自审核 Config 的 Result Text。

### 3.3 旧流程模型落点与新流程调用矩阵

旧 P1–P10 流程实际没有把 Gemini 或 GLM 固定分配到各阶段。它们只是 Canvas runtime 已支持的可选文字模型。旧流程明确绑定的文字模型只有：

- P4 正式配音前，DeepSeek V4 Flash GA 正式版（`deepseek-v4-flash-ga-260731`）做逐字保真的语气分段，再交给 Seed-TTS；
- 旧 P7 H3 Prompt 使用豆包 Seed 2.1 Turbo 和受管理 H3 System Prompt；
- P2 只写“原生文字模型调用”，没有指定 Gemini 或 GLM；
- P3 默认使用 Nano Banana Lite 生图；P5 Storyboard 标准模式使用 GPT Image 02，快速模式使用 Nano Banana Lite；P6/P8 是 H3 链，不需要为每个中间 Text 再调用 Gemini/GLM。

新流程延续“关键节点才外置调用”的原则：

| 阶段 | 默认由 Codex / Script / MCP 完成 | 外部文字模型调用 | 说明 |
|---|---|---|---|
| P1 | 收集需求、完整性检查、资源索引、项目简报结构化 | 无 | 规则确定，不值得再做 Gemini + GLM 双调用 |
| P2 | 来源研究、Claim/source 记录、source verification、事实 Gate、回流和版本锁定 | Gemini：主题分析 + 内容大纲一次；Gate 通过后生成剧本初稿一次；GLM：最终校定/去 AI 化一次 | P2 的事实核验由 Codex 调研直接完成，不再增加外部审核调用 |
| P3 | 从锁定剧本提取角色/场景/道具需求，复用已有资产，组装固定图片约束 | Gemini：仅当需要新建或实质改造角色/Variation/声音/场景设计时，做一次 P3 综合创意设计；已有资产全部满足时不调用 | 四视图和场景整合图由图片模型生成；默认不用 GLM 逐项复审 |
| P4 | 绑定剧本片段和 P3 资产、建立 shot IDs、按文字预估生成时长、确定性连续性检查 | Gemini：全片导演总纲 + 正式分镜设计作为一次阶段任务；GLM：全部 P4 完成后做一次跨分镜总审 | 不先生成音频；不为每个分镜串联一次 GLM；超出上下文时可按批次运行 Gemini，但仍是同一阶段任务 |
| P5 | 用固定模板组装 Storyboard Prompt、引用排序、验收记录 | 无通用文字模型 | 标准模式由 GPT Image 02 生成 Storyboard；用户选择快速模式时使用 Nano Banana Lite；确定性 Rubric + 人工查看验收 |
| P6 | 汇总 runtime brief、引用排序和输入快照 | 豆包 Seed 2.1 Turbo：按现有 H3 System Prompt 生成正式 H3 Prompt | Result 直接锁定，不运行 Prompt validator 或双模型审核 |
| P8 | H3 依赖调度、实测时长、Codex 直接视频理解、统一综合评估和定向处理 | MiniMax H3 生成；默认不调用外部视频理解模型 | 不执行 P7；生成/技术问题只重生成，承载问题才回 P6，且不改 P4 |

DeepSeek V4 Pro 不再固定绑定新版 P1–P8，但 Canvas runtime 仍保留给用户直接操作。正式 Speech 生成链另行使用 DeepSeek V4 Flash GA 正式版（`deepseek-v4-flash-ga-260731`）负责语气分段。

## 4. P1 — 项目需求与创作边界

### 目标

回答“要做什么项目”，不编剧，不做导演设计，不生成角色或场景图。

### 输入

- Topic；
- 目标受众；
- 内容方向；
- 目标片长、画幅及发布环境；
- 正式角色选择、用户指定 NPC；
- 已有角色、场景、品牌和视觉参考；
- 用户明确的风格偏好、禁区和不可改变条件；
- Auto / 互动、Canvas / Skill 原生。

### Canvas 工作列

```text
P1-A 用户原始需求与约束 Text
P1-B 已有角色 / Voice / 资源索引
P1-C Codex / 规则校验形成项目简报 Text
P1-D 缺失项或冲突项 Comment / Gate 状态
```

### 锁定产物

- 项目简报；
- 角色与现有资产索引；
- 用户硬约束；
- 允许模型补全的范围；
- 待后续解决的问题。

## 5. P2 — 主题、大纲、事实 Gate 与最终剧本

### 阶段定位

P2 的最终剧本是 P3–P8 的权威叙事依据。导演总纲、角色与场景设计、文字分镜、Storyboard 和 H3 Prompt 都必须从当前已确认的最终剧本派生。

### 5.1 P2-A 主题分析

先基于 P1 明确：

- 核心问题；
- 受众认知起点；
- 本片只解决什么；
- 明确不讲什么；
- 候选钩子；
- 候选叙事路线；
- 预期观众收获。

输出是**主题分析候选 Result**，不是事实已通过的结论。

### 5.2 P2-B 内容大纲

基于主题分析形成**待事实核验的大纲**：

- 叙事段落和知识节拍；
- 每段知识目的；
- 角色在该段的叙事功能；
- 计划使用的事实、概念、类比或实验；
- 可见事件与证据方向；
- 情绪和认知转折；
- 临时时间预算；
- 前后段落依赖。

大纲必须为每个计划事实分配稳定条目，供事实依据逐项核验。

### 5.3 P2-C 事实依据、Codex source verification 与 Gate

事实依据不在流程最前面，而是对待核验大纲进行定向研究和逐项验证。

每个大纲条目至少记录：

- 待验证主张；
- 来源和链接；
- 来源支持的准确表述；
- 必须保留的限定条件；
- 适龄解释；
- 对应大纲位置；
- 结论：`supported` / `revise-outline` / `remove` / `user-decision`。

Codex 在同一次事实研究中完成 source verification：检查证据是否足够支持大纲主张、推论是否越界、限定条件是否保留、来源与结论是否错配，以及哪些条目必须回改大纲。此处不再调用独立外部审核模型。

Gate 规则：

```text
待核验内容大纲
        ↓
Codex 事实研究、Claim/source 映射与 source verification
        ↓
Codex 事实 Gate 记录
        ├─ FAIL → 回到内容大纲 Config 修订 → 重新事实核验
        └─ PASS → 调用 Gemini 进入剧本初稿
```

不得为了让事实 Gate 通过而弱化、歪曲或拼接证据；证据不支持时必须修改或删除大纲内容。

同一版大纲通过后，其事实 Gate 结果成为剧本生成的权威事实输入。后续 GLM 去 AI 化不再重复查询来源或重新做一遍全量事实审核。只有大纲主张、事实内容或限定条件发生变化时，才重新进入本 Gate。

### 5.4 P2-D 剧本初稿

只有事实 Gate 通过后才能形成剧本初稿。剧本锁定：

- 故事与知识结构；
- 事件和因果顺序；
- 角色功能与关系；
- 必须发生的行为、发现、反应和转折；
- 旁白与对白；
- 必须呈现的可见证据；
- 剧本层的场景语义；
- 高层情绪发展；
- 结尾如何兑现开场。

剧本不锁定正式镜头、机位、运镜、景深、Storyboard 画格或 H3 Prompt。

### 5.5 P2-E GLM 去 AI 化与最终剧本锁定

剧本初稿形成后，GLM 的后置职责是**去 AI 化与表达校定**，不是第二次事实依据审核。它至少处理：

- 旁白 / 对白是否自然、可说、符合角色；
- 句式是否机械、平均、模板化；
- 是否存在重复解释、空话、套路化排比和 AI 腔；
- 语言是否适龄、克制且有人类表达节奏；
- 是否完整保留已通过事实 Gate 的事实、限定条件、大纲结构、角色功能、事件因果和顺序；
- 是否在润色过程中擅自加入或改写内容。

GLM 后置节点不得重新选择主题、重做大纲或以“事实审核”为名改写已通过 Gate 的内容。若发现 Gemini 剧本初稿偏离已通过的大纲/事实，它应标记为`script-drift`并要求重新生成剧本初稿；只有需要改变大纲或事实时才返回前置事实 Gate。

Canvas 链：

```text
事实 Gate PASS + 当前内容大纲 Result
        ↓
Gemini 剧本 Config → 剧本初稿 Result
        ↓
GLM 去 AI 化 / 表达校定 Config
        ↓
去 AI 化后的最终候选剧本 Result
        ↓
强制用户确认
```

### P2 强制门禁

无论 Auto 还是互动模式，都必须向用户展示当前完整剧本并暂停。只有用户明确确认后，才能记录剧本版本、哈希和确认时间并进入 P3。

用户要求修改时：

- 只改措辞且不改变事实、大纲和因果：把用户反馈作为输入重新运行 GLM 去 AI 化 / 表达校定 Config，不重新做事实 Gate；
- 改主题、知识点、事实、钩子、结构或因果：退回相应的大纲条目，并重新通过事实 Gate；
- 未重新确认的新剧本不得进入 P3。

## 6. P3 — 角色、音色、剧本场景与道具的前期设计资产

### 阶段定位

P3 不做分镜拆解，也不建立独立连续性矩阵。它消费已确认剧本，完成角色和剧本级大场景的前期设计资产，为 P4 导演分镜提供稳定 Reference。

P3 的图片是角色/场景设计参考资产，不是正式 Storyboard 或成片画面。

### 6.1 P3-A 角色需求清单

从最终剧本提取：

- 角色名称与类型；
- 在剧本中的功能；
- 出现的剧本段落和场景；
- 必须完成的动作和互动；
- 剧情要求的情绪范围；
- 是否已有全局角色资产；
- 是否需要新建临时 NPC；
- 剧本要求的 Variation；
- 是否需要对白、旁白或仅视觉表演；
- 当前可用 Voice ID / 参考音色 / 参考音频。

### 6.2 P3-B 每角色总体设定

每个角色形成一份生产级角色设定：

- 剧本功能、性格和关系；
- 身份与不可改变识别锚点；
- 年龄感、体型、比例、轮廓和面部结构；
- 发型/毛发、表面特征；
- 默认服装、材质、配色、鞋履和固定配件；
- 站姿、重心、动作习惯和表情范围；
- 剧本要求的 Variation：服装、状态、污损、发型、情绪外显等，以及出现原因和适用剧本场景；
- 禁止变化项。

### 6.3 P3-C 角色音色设定与参考

每个需要发声的角色至少定义：

- 年龄感和音高范围；
- 音色质地；
- 能量、节奏和停顿习惯；
- 咬字清晰度、口音和语言风格；
- 情绪变化范围；
- 禁止特征；
- Voice ID（已有时）；
- 参考音频 Resource（已有时）；
- 新角色需要后续建设的 Voice Prompt / Voice Asset。

已有角色优先复用已同步的角色图、Voice ID 和参考音频，不为本项目静默重建全局身份。参考音频应作为真实 Audio / Resource 节点进入后续语音或视频 Config，不只把文件名写进文字。

### 6.4 P3-D 四视图角色参考图

角色四视图在 P3 完成，P4 不再重新设计。固定结构：

- 左侧：一张大幅半身主图；
- 右侧依次：正面全身、侧面全身、背面全身；
- 四个区域保持身份、比例、服装、材质和配色一致；
- 三个全身视图完整不裁切。

已有且已验收的角色四视图直接复用；缺失时走真实 Image Config 生成和验收。旧三视图提示词不能原样复用，需要四视图专用提示词资产。

### 6.5 P3-E 剧本场景与道具需求清单

场景从最终剧本提取，不从分镜反推。这里的场景是剧本级的大场景 / 固定空间，而不是某个分镜中的构图。

每个剧本场景至少记录：

- 稳定 `sceneId` 与场景名称；
- 对应剧本范围和叙事功能；
- 地点、时间、天气和氛围；
- 空间结构与尺度；
- 固有色、材质和固定光源；
- 固定家具、标志物和背景元素；
- 剧情关键道具；
- 可移动小型道具；
- 出场角色；
- 剧本要求的场景状态变化；
- 已有场景资源及缺失项。

这里不决定具体分镜机位、景深、运镜或画面节奏。

### 6.6 P3-F 每场景综合设定图

推荐每个剧本场景默认形成**一张综合场景设定图**，把后续导演和生成需要的场景信息集中在同一资产中：

- 一个占主要面积的场景主视图，锁定整体空间、比例和视觉气质；
- 必要的辅助方向或空间覆盖小视图；
- 剧情关键道具与小型道具展示区；
- 关键时间/光线状态的必要变体；
- 保持同一建筑、材质、家具、道具尺度和空间关系；
- 不做连续 Storyboard，不表现分镜顺序；
- 默认避免可读文字、箭头和技术批注污染后续 Reference。

如果一个所谓“场景”无法在一张综合图中清楚表达，应优先检查它是否实际包含多个固定空间；拆分为多个 `sceneId`，而不是无限增加同一场景的散图。是否允许少量辅助图作为例外，标为待用户确认。

### P3 输出

- 角色需求清单；
- 每角色总体设定；
- 角色 Variation；
- 音色设定、Voice ID 与参考音频绑定；
- 已验收角色四视图；
- 剧本场景与道具清单；
- 每个剧本场景的综合设定图；
- 已有 / 复用 / 缺失资产台账。

## 7. P4 — 导演公共规则与逐分镜文字设计

### 阶段定位

P4 基于最终剧本和 P3 已锁定角色/场景资产，完成“怎么拍”的文字导演策划。P4 不重新编剧，不重新设计角色身份或场景固有结构，也不生成 Storyboard。

P3 与 P4 的视觉边界：

- P3 锁定角色、服装、场景建筑、道具、固有配色和基础材质；
- P4 决定摄影 / 渲染如何呈现这些资产：画面风格、光线处理、色彩处理、镜头、景深、运动、表演、节奏和声音；
- P4 若需要改变 P3 固有资产，必须回流 P3 更新并重新验收，不能在分镜提示里偷偷覆盖。

### 7.1 P4-A 全片导演公共列

剧本和 P3 已经解决“讲什么、角色是谁、场景是什么”，因此公共列只保留真正影响导演拍摄的一致性规则。

推荐四个公共 Result：

#### 1. 导演总纲与观看关系

- 导演意图；
- 叙事视角；
- 观众与角色 / 知识的距离；
- 情绪温度和全片变化；
- 写实、夸张、喜剧或戏剧表达尺度；
- 全片必须避免的表达俗套。

#### 2. 画面、摄影与镜头语法

- 总体画面质感；
- 色彩处理和明暗对比；
- 光线使用方式；
- P3 材质在镜头中的呈现原则；
- 构图、画幅和安全区；
- 景别、角度和视角偏好；
- 焦段倾向、透视和景深；
- 静态镜头与运镜的使用条件；
- 运镜速度、方向和停止原则；
- 转场与剪辑语法。

#### 3. 全片节奏、信息密度、表演与动态

- 全片节奏曲线；
- 信息密度、停顿和留白；
- 开场抓力、发展、转折和收束；
- 人物表演尺度；
- 站位、调度和动作可读性；
- 人物动效与环境动效强度；
- 什么情况下画面应保持静止。

#### 4. 全片声音导演规则

- 音乐的叙事功能和风格范围；
- 音乐进入、退出、强弱和留白；
- 环境音层级与空间感；
- 关键音效使用原则；
- 对白 / 旁白与画面的主次；
- 声画同步、提前、延后和反差原则；
- 禁止的声音俗套。

### 7.2 P4-B 根据最终剧本拆分文字分镜

Storyboard Unit 初步拆解不再放在 P3。P4 导演策划首先根据以下条件把最终剧本拆成正式文字分镜：

- 每段知识或叙事目的；
- 必须呈现的可见证据；
- 动作和角色状态变化；
- 场景或时间变化；
- 视觉注意重点；
- 镜头语言变化；
- H3 单分镜生产边界；
- 前后分镜连续性。

拆分只改变视觉承载方式，不得改变剧本事实、台词、事件和因果顺序。

### 7.3 P4-C 每个文字分镜的最终内容

每个分镜一个工作列，并至少包含：

1. 分镜 ID、对应剧本片段、预估生成时长和时长依据；
2. 知识 / 叙事目的，观众必须注意什么；
3. 起始状态、结束状态及相对前后分镜的变化；
4. 引用的 P3 场景综合设定图；一个分镜可按剧本需要涉及一个或多个场景；
5. 出场角色、引用四视图、当前 Variation、Voice / Audio Reference；
6. 道具、持握、摆放和状态变化；
7. 人物关系、调度、互动、动作顺序、表情、视线和情绪；
8. 构图、景别、角度、机位、焦段意图和景深；
9. 运镜动机、路径、方向、速度和停止状态；
10. 画面 / 环境动效；
11. 旁白、对白和用户明确要求的画面文字；
12. 音乐、环境音、关键音效和声画关系；
13. 与前后分镜的连续性、依赖和需要继承的状态；
14. Storyboard 与 H3 Prompt 后续必须继承的约束；
15. 必须避免的错误和当前待确认项。

预估生成时长不依赖预先生成音频：按对白/旁白文字朗读时间、无法并行完成的动作、前后留白依次估算，再向上取整为 3–15 秒整数。它只是 P6/P8 的初始目标参数，不是最终视频时长。单个片段承载不足时，保持 P4 `shotId` 和整体导演规划不变，由 P6 建立多个生成片段；优先在场景切换或本来不连续的画面/动作边界拆分，非必要不拆连续动作。

连续性和依赖直接写进对应分镜及相邻分镜关系，不在 P3 单独建立一份先验矩阵。P4 跨分镜审核可以从这些分镜关系生成全局问题清单，但不另造一套冲突的事实来源。

### 7.4 P4 Canvas 阶段节点链

```text
最终剧本 + P3 全部当前资产
        ↓
Gemini P4 导演总纲与正式分镜设计 Config
        ↓
导演总纲 + 全部分镜草案 Result Text
        ↓
Codex / Script 拆分并组织到公共列和各 shot 列
        ↓
GLM P4 跨分镜总审 Config（整阶段一次）
        ↓
总审 Result Text
        ↓（有问题时）
只重跑受影响的 Gemini 分镜批次 → GLM 复核受影响分镜与相邻边界
```

GLM 不对每个分镜逐一串联审核，只在全部 P4 草案形成后执行一次跨分镜总审，检查剧本覆盖、角色、场景、道具、动作、空间、光线、镜头方向、情绪、声音和连续性。受影响分镜通过 Gemini Config 重生，MCP 不直接改模型 Result。

### P4 输出

- 全片导演公共规则；
- 正式文字分镜列表；
- 每个分镜的当前有效导演策划 Result；
- 跨分镜审核结果；
- 后续 Storyboard / H3 必须继承的约束；
- 当前依赖和失效关系。

## 8. P5 — Storyboard 提示词、生成、验收与锁定

### 阶段定位

P5 不再重新设计文字分镜，而是把 P4 已定稿的每个文字分镜转化成 Storyboard Prompt 和 Storyboard Image。

### 每分镜输入

- P4 当前有效文字分镜；
- P4 全片导演公共规则；
- P3 角色四视图；
- P3 场景综合设定图；
- P3 道具和 Variation；
- 前后分镜连续性。

### Canvas 节点链

```text
P4 分镜 Result + P3 References
        ↓
Codex / Script 按固定模板组装 Storyboard Prompt Text
        ↓
Storyboard Image Config
        ↓
Storyboard Image Result
        ↓
Storyboard 视觉验收 / 重生
        ↓
当前已验收 Storyboard
```

Storyboard 只负责把 P4 的镜头顺序、构图、调度、动作、景深、运镜和连续性可视化，不得改写剧本或重新发明导演方案。

### P5 输出

- 每分镜 Storyboard Prompt；
- 已验收 Storyboard Image；
- Reference 顺序和输入快照；
- Storyboard 版本和验收状态。

## 9. P6 — 正式 H3 镜头提示词锁定

### 阶段定位

P6 为每个已验收 Storyboard 生成正式 H3 生成片段提示词。P6 后直接进入 P8，不再生成 Trailer/Pre-roll。一个 P4 `shotId` 默认对应一个生成片段；只有时长承载不足时才在同一 `shotId` 下增加 `generationSegmentId`。

### 每分镜输入

- P4 当前有效文字分镜；
- P4 全片导演公共规则；
- P5 当前已验收 Storyboard；
- P3 场景综合设定图；
- P3 角色四视图与 Variation；
- Voice / Audio Reference（当前已有时）；
- 当前 H3 模式对应的受管理 System Prompt；
- P4 预估生成时长及依据；
- 前镜尾帧依赖规划（如适用）。

### Canvas 节点链

```text
H3 System Prompt Text + 当前分镜文字 / 图片 / 音频输入
        ↓
豆包 Seed 2.1 Turbo H3 Prompt Text Config
        ↓
H3 Prompt Result Text
        ↓
当前锁定 H3 Prompt Result + 目标生成时长 + 有序素材清单
```

P6 不生成正式 H3 视频，只锁定提示词、Reference 顺序、模式、`targetDurationSeconds` 和输入快照。Prompt 不运行本地或外部内容 validator。

## 10. P7 — 已取消，不执行

固定流程从 P6 直接进入 P8。不得创建 Trailer 压缩 Brief、独立预演 Prompt、Preview Video、P7 列或 P7 approval，也不调用旧 P7 DeepSeek V4 Flash 压缩任务。

## 11. P8 — 正式 H3 分镜画面生成

### 进入条件

- P2 当前剧本确认仍有效；
- P3 当前角色、场景和道具资产有效；
- P4 当前导演公共规则及全部文字分镜有效；
- P5 Storyboard 已验收；
- P6 全部正式 H3 Prompt 已锁定；

### 执行

使用全部 P6 当前 H3 Prompt、P5 Storyboard和 P3 角色/场景 Reference 生成正式 H3 分镜画面。

- 独立分镜可并行；
- 真实连续依赖链必须串行；
- 前镜尾帧依赖必须使用实际生成尾帧；
- 任一上游内容或资源变化，只使引用它的 Prompt、Storyboard、H3 和综合评估记录失效；
- 每段生成后探测 `actualDurationSeconds`，由 Codex 直接查看真实 Video，并结合 P2 锁定剧本、P4 规划、P6 Prompt/片段映射、目标/实际时长做统一综合评估；
- 总评通过时锁定当前 Video；生成或技术质量问题保持 P6 不变并重生成当前片段，承载/拆分问题才回 P6 延长、拆分或增加延续片段，再重跑受影响 P8 链。

P6 拆分优先在场景切换或本来不连续的画面/动作边界，使新片段保持 `independent`/`soft-continuity`；非必要不拆连续动作，无法避免时才使用 `tail-frame`。不得改变 P4 `shotId`、剧本覆盖、事件顺序或导演规划。

### 本稿终点

P8 视频综合评估通过后停止。本文暂不定义：

- 正式对白 / 语音生成的最终插入位置；
- H3 分镜的 ASR 和三帧人工视觉验收；
- 定向重做；
- 合片；
- 成片交付。

## 12. Canvas 总体空间结构

推荐从左向右按阶段推进，并让 P4 之后按分镜形成稳定的纵向生产列。

```text

        →
[P2 主题] [P2 大纲] [P2 事实 Gate] [P2 剧本] [P2 强制确认]

[P3 角色清单] [每角色设定 / 四视图 / Voice]
[P3 剧本场景清单] [每场景综合设定图]
        →
[P4 导演公共规则]
        →
[Shot 01] [Shot 02] [Shot 03] ... [Shot N]
   │          │          │              │
 P4文字     P4文字     P4文字         P4文字
```

## 13. 阶段边界汇总

| 阶段 | 决定什么 | 不决定什么 |
|---|---|---|
| P1 | 项目、受众、角色选择、约束 | 剧本与导演设计 |
| P2 | 主题、大纲、事实、最终剧本 | 正式镜头和视觉资产 |
| P3 | 角色、Variation、音色、四视图、剧本级场景和综合场景设定图 | 分镜拆解和镜头语言 |
| P4 | 全片拍摄规则、正式文字分镜、每镜导演策划和预估生成时长 | Storyboard 图片、H3 Prompt 和最终视频时长 |
| P5 | Storyboard Prompt、Storyboard 图片及验收 | 重写剧本或重新导演 |
| P6 | 正式 H3 生成片段提示词、目标时长与素材顺序；必要时在同一 `shotId` 下拆分/扩展 | 改写 P4 分镜规划 |
| P7 | 已取消，不执行 | 不创建 Trailer/Pre-roll |
| P8 | 正式 H3 Video、实测时长与统一综合评估闭环 | 拼接和交付 |

## 14. 当前需要用户确认的政策

1. P3 的角色四视图和综合场景设定图是否作为所有模式的强制人工确认 Gate，还是仅互动模式暂停、Auto 模式按验收规则自动继续。
2. 每个剧本场景是否默认严格限制为一张综合设定图；物理空间确实复杂时是否允许少量辅助图。
3. 综合场景设定图的固定版式是否采用“主空间大图 + 辅助方向小图 + 道具展示区”，以及是否完全禁止文字标注。
4. P8 综合评估记录是否还需要用户逐段确认；当前固定流程只要求 P2 强制人工 Gate。
5. P5 Storyboard 完成后是否为所有模式的强制用户 Gate，还是互动模式确认、Auto 模式验收通过后继续。
6. P6 暂按旧链继续使用豆包 Seed 2.1 Turbo，Result 不运行 Prompt validator；如需改用其他模型，应作为单独产品政策和对照测试决定。
7. 正式对白 / 旁白语音在哪个阶段生成。若 P8 H3 需要准确口型同步，正式音频必须在 P6 Prompt 锁定或 P8 生成前成为真实 Audio Reference。
8. P8 所称“正式 H3 分镜画面”是否包含 H3 原生声音；在语音阶段未确定前，本文不假设它已经具备最终对白和音乐。

## 16. 与当前实现的主要差异

- P2 从“事实先行”改为“主题 → 大纲 → 定向事实 Gate → 回查大纲”。
- P2 最终剧本新增所有模式强制人工确认。
- P3 不再提前拆 Storyboard unit 或独立连续性矩阵；改为角色、Variation、音色、四视图、剧本场景与综合场景设定图。
- P4 从当前配音阶段改为导演公共规则和逐分镜文字策划。
- P5 只负责基于 P4 定稿分镜生成和验收 Storyboard。
- P6 负责正式 H3 Prompt 锁定与同一 P4 分镜内的生成片段化。
- P7 Trailer/Pre-roll 被取消，P6 直接进入 P8。
- P8 生成正式 H3 分镜画面后做统一综合评估；生成/技术问题只重生成，承载问题才回 P6 拆分/扩展。
- 当前 P9/P10 验收与合片不在本稿讨论范围。

上述差异意味着未来若实施，固定阶段规范、Canvas 节点产物契约、MCP schema/描述、Skill 原生目录与脚本、提示词资产、门禁和失效逻辑都必须成套更新；本稿阶段不进行任何实现修改。
