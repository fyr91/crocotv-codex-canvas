# P6–P8 H3 Prompt 与视频生成规范

## 受管理 System Prompt

所有 H3 Prompt 统一逐字使用 [Ref2VA 通用 System Prompt](H3-Ref2VA-System-Prompt.txt)，固定记录 `templateKey: croco.h3.universal-ref2va`、`templateVersion: 2.0.0` 和内容 SHA-256。脚本读取文件完整字节作为唯一 `system` message，不得 trim、拼接、摘要、翻译或在代码中追加隐式系统指令；runtime brief 与多模态引用只进入独立 `user` message。不再根据 T2VA、I2VA、FL2VA、L2VA 或 Ref2VA 输入模式选择不同 System Prompt；这些模式只描述 H3 请求接收的真实媒体与帧约束，不改变六段式 Prompt 契约。

静态 System Prompt 只作为 system message；P4 文字分镜、P5 Storyboard、P3 资产、音频和运行参数只进入 user 输入/真实媒体引用。旧 T2VA/I2VA/FL2VA/L2VA 模板仅保留给历史项目核对，不得连接到当前 P6 Text Config，也不得由原生脚本读取。

## P6 正式 H3 Prompt

逐个正式 `shotId` 汇总：

- P4 锁定文字分镜和导演总纲；
- P5 当前 Storyboard（规划参考，不是待复刻首帧/关键帧）；
- P3 场景综合设定图、角色四视图/Variation 和道具；
- 用户明确要求的画面文字；
- H3 模式、P4 预估生成时长、画幅、连续性与前镜依赖；
- 已存在且本镜需要的真实音频引用；正式 Speech 尚未启用时不得虚构 Audio。

使用 `.codex/.env` 的 `ARK_MODEL` 调用豆包 Seed 2.1 Turbo。豆包直接生成 Ref2VA 通用 System Prompt 规定的最终六段式 Prompt；真实音频的 `<Audio N>` 角色和顺序在 runtime brief 中先确定，再由豆包写入六个官方字段，不得在输出后追加 `audio_references:` 等第七字段，也不让模型猜测文件。

H3 Prompt Result 不再经过本地或外部内容 validator，不做六字段、标签、枚举、时码或画面文字的事后审核/修复。受管理 System Prompt 自身承担输出规范；执行层只拒绝空响应和超过 H3 20,000 字符硬上限的响应，不评价或改写 Prompt 内容。

P4 的 `预估生成时长` 进入 P6 时称为 `targetDurationSeconds`，限制为 3–15 秒整数。它来自对白/旁白文字预估、非并行动作、前后留白和向上取整，不要求先生成音频。若完整 `shotId` 无法在单片段承载，P6 在同一 P4 分镜下建立多个 `generationSegmentId`，不得改动剧本覆盖、事件顺序或导演规划。优先在场景切换、本来不连续的画面/动作边界拆分，使片段保持 `independent` 或 `soft-continuity`；非必要不拆连续片段，只有无安全断点时才建立 `tail-frame`。

最终锁定当前模型 Result。保存 Ref2VA System Prompt 的 `templateKey/templateVersion/SHA-256`、最终 Prompt SHA-256 和完整输入快照。

无尾帧依赖时，图片顺序为 Storyboard → 场景综合设定图 → 角色四视图/Variation；有 `tail-frame` 时 `<Picture 1>` 为前镜尾帧，Storyboard 和其他 Reference 顺延。标签顺序必须与 Canvas composer/原生上传顺序一致。

画面文字默认完全禁止。旁白、对白、歌词、知识点、自动策划字段或参考图文字都不构成授权；只有 P2/P4 明确标记“用户明确要求的画面文字”的精确原文可进入 Prompt，并禁止除此之外的字幕、标题、标签、UI、Logo、水印、字母、数字和其他可读文字。

保存 `Prompt锁定` 只表示当前模型 Result、System Prompt、References 和输入快照被选为 P8 来源，不表示另做内容审核。P8 一致性分析不得直接改写 Result；需要调整时以分析 Result 为新输入，在 P6 产生新的拆分/扩展版本并保留历史。

## P6 → P8 直接执行

P6 锁定后直接进入 P8，不再执行 P7 Trailer/Pre-roll，不创建压缩 Prompt、Preview Video 或 P7 approval，也不调用原 P7 DeepSeek V4 Flash 压缩链。

## P8 正式 H3 视频与综合评估闭环

H3 同时接收 P6 锁定 Prompt 与同一快照中的有序媒体。图片最多 9 张、音频最多 3 段、Prompt 最长 20000 字符。Profile 由项目原生画幅决定：

- 16:9：`preview`（864 × 480）；
- 9:16：`portrait_preview`（480 × 864）；
- 4:3：`standard_480p`（640 × 480）；
- 3:4：`standard_portrait_480p`（480 × 640）。

固定 `steps: 20`、`ref_image_size: match`。不得通过裁切、模糊补边或画布转换冒充目标画幅。

`tail-frame` 必须等待前镜成功并提取最后一个可解码帧，把它作为后镜 00:00.000 精确首帧。每个成功分镜保存 `尾帧.png`、`lastFramePath`、`lastFrameSha256`。前镜失败时后镜为 `blocked-by-dependency`，不得退回独立生成。场景切换或不连续边界拆出的片段不得为了方便而增加 `tail-frame`。

依赖链内部串行；所有独立链的豆包 Prompt、素材上传和 H3 视频任务立即并发，不设置 Skill 级并发上限。非流式豆包等待上限 420 秒，H3 异步轮询到终态，稳定 UUID 幂等并支持恢复。Provider 限流或排队按真实返回状态处理，不回写为全局并发配置。

`H3参考素材.json` 记录 schema、画幅/Profile/宽高、`storySegmentId`、有序 `sceneIds`、场景/角色/Storyboard/音频引用与 SHA-256、文字分镜、导演总纲、System Prompt、P6 lock、前镜 Job/尾帧和完整输入快照。任一输入、顺序或哈希变化时旧 Prompt/Video 移入历史并只使受影响依赖链失效。

并发写状态必须串行持久化；临时文件名包含 PID 和随机 UUID。已有 `当前视频.json.status: succeeded` 且快照匹配时可跳过。参考音频始终完整上传，不裁剪；请求的 `duration_seconds` 必须为 3–15 秒整数，并记录为目标生成时长。P8 完成后用媒体探测得到 `actualDurationSeconds`；只有这一实测值可称为当前视频的实际时长，P4/P6 数值不得命名为最终视频时长。

每个 P8 Video 生成后，由当前 Codex/Skill 本体按 [P8 视频综合评估规范](P8-视频综合评估规范.md)直接查看真实 Video，并结合 P2 锁定剧本、P4 文字分镜、P6 当前 Prompt/片段映射、目标与实测时长完成一次统一综合评估。默认不调用外部视频理解模型，也不通过脚本理解视频；用户明确指定外部模型时才按其选择执行。FFprobe 等脚本只读取确定性的媒体时长和编码信息，不产生内容判断。

综合总评为 `pass` 时锁定当前 Video；为 `regenerate` 时保持 P6 不变，仅重生成当前 P8 片段；为 `revise-p6` 时回到 P6，只允许以下修订：

- 在同一 `shotId` 下按场景切换或不连续画面/动作边界拆分 `generationSegmentId`；
- 在 15 秒上限内延长片段目标时长；
- 为未完整呈现的同一规划内容增加相邻延续片段。

优先选择不产生依赖的拆分点。只有评估证据明确证明连续动作无法在安全断点承载时，才创建 `tail-frame`。P6 新版本不得改变 P2 剧本文字、P4 分镜目的、事件顺序、镜头规划或整体导演判断；若问题必须改动这些上游内容，标记 `blocked-upstream` 并停止自动回流。修订后只重跑受影响 P6/P8 片段及真实依赖链，再做统一综合评估，直至通过或需要用户决策。P8 不自动合片。

## P8 之后保留的按需能力

以下核心能力继续保留，但不属于当前 P1–P8 自动流程：

- 火山 ASR 对白逐字验收、无计划人声检测和定向重做；
- 供用户追加的专项人工复核；P8 综合评估已经覆盖角色/场景/跨镜连续性、可读文字和常见技术缺陷，不重复设置默认验收流程；
- 只重做受影响分镜与依赖链；
- 合片前源哈希、原生 Profile、完整解码、音频和 PCM SHA-256 校验；
- 只有当前验收通过且快照有效的正式 Video 才可 `mergeEligible: true` 并进入安全合片。

原生继续复用 `验收H3对白.mjs`、`验收H3视觉.mjs`、`合并H3分镜视频.mjs`；Canvas 继续复用 ASR、视频帧、视觉验证与 merge 工具。后续阶段未被用户定义前，不自动调用或重新编号。
