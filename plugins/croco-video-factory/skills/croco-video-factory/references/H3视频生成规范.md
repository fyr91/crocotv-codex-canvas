# H3 视频生成规范

## P7 H3 Prompt

只有[Pre-roll 确认规范](Pre-roll确认规范.md)定义的 P6 `approvalSnapshot` 与当前 Pre-roll Video SHA-256 和输入快照一致时，才能进入 P7。逐个分镜组读取以下前置产物：

- `分镜内容.md`：当前视频片段的内容、镜头、台词、音效和最终时长。
- `整体视觉风格.md`：整条视频统一的成片风格与表演边界。
- `当前分镜图.json` 指向的 Storyboard：镜头顺序、构图、调度、动作、运镜、转场和 dynamics 的规划参考。
- `场景参考图.json` 中已验收的故事场景设计图：锁定空间布局、光向、色彩、材质、固定家具和道具锚点。
- `角色参考图.json` 中当前片段实际出镜角色的设计图：锁定身份、物种、年龄、体型、五官、服装和可识别特征。

当前链路固定使用 Ref2VA/R2V。原样读取 [Ref2VA 静态 System Prompt](H3-Ref2VA-System-Prompt.txt) 作为 system message；上述运行时文字和图片只放入 user message。使用 `.codex/.env` 中的 `ARK_MODEL` 调用豆包 Seed 2.1 Turbo，输出基础 H3 Prompt。音频文件不发送给豆包，也不让豆包推断音频 Reference。

豆包返回后，脚本按 `旁白或对白音频/` 中的真实文件顺序追加 `audio_references:`：`<Audio 1...N>` 必须写明对应角色、旁白或对白类型、是否需要口型同步，以及原始完整音频必须直接复用。相同标签顺序写入 `视频生成/H3参考素材.json`，最终保存为 `视频生成/视频提示词-优化后.md`。

## Reference 角色

无前镜尾帧依赖时，`<Picture 1>` 为 Storyboard 规划参考，后续先排列场景设计图，再排列角色设计图。Storyboard 不是首帧、尾帧、关键帧或待复刻画面，不得继承黑白草图、分格排版、批注或编号。场景设计 Reference 是可重构镜头的环境不变量，不是固定帧；角色 Reference 只锁定角色设计。`<Audio 1...N>` 在豆包输出后追加，提供真实旁白或对白音频。

豆包生成的基础 MiniMax Prompt 固定输出 `subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`；脚本只在其后追加确定性的 `audio_references`。画内发声需口型同步；画外旁白时画面角色嘴巴闭合。

画面文字默认完全禁止。对白、旁白、歌词、科普内容、自动策划出的 `屏幕文字` / `画面文字` 字段或参考图中已有文字都不构成字幕、标签或转录授权；只有运行时分镜明确标记为“用户明确要求的画面文字”的精确文字才允许进入 H3 Prompt，并且必须同时禁止除此之外的字幕、标题、标注、UI 文字、Logo、水印、字母、数字或其他可读文字。该规则必须写在受管理的静态 System Prompt 中，不得由调用代码隐藏追加。

## P8 H3 视频生成

H3 同时接收 `视频提示词-优化后.md` 与 `H3参考素材.json` 中按标签排序的 Storyboard、角色设计图和音频 References。图片最多 9 张、音频最多 3 段、Prompt 最长 20000 字符。Profile 必须由 `分镜计划.json.aspectRatio` 决定：16:9 使用 `preview`（864 × 480），9:16 使用 `portrait_preview`（480 × 864），4:3 使用 `standard_480p`（640 × 480），3:4 使用 `standard_portrait_480p`（480 × 640）；统一使用 `steps: 20`、`ref_image_size: match`。不得先生成其他画幅再通过裁切、模糊补边或画布转换冒充目标画幅。

没有 `tail-frame` 依赖时：`<Picture 1>` 为 Storyboard，后续按“场景设计图 → 角色设计图”排列。存在 `tail-frame` 依赖时，必须先等待前置分镜成功并提取最后一个可解码帧；`<Picture 1>` 改为该尾帧并作为 00:00.000 的精确首帧，Storyboard 顺延为 `<Picture 2>`，场景和角色设计图依次后移。同 `storySegmentId` 与 `sceneId` 的相邻 clip 必须使用该依赖链；图片总数仍不得超过 9。

每个成功分镜保存 `尾帧.png`，并在 `当前视频.json` 记录 `lastFramePath` 和 `lastFrameSha256`。任务调度按 `分镜计划.json` 的依赖图运行：硬依赖链内部串行，不同链与独立分镜继续共享最多 5 路 H3 并发；依赖镜头的豆包 Prompt 只在前镜尾帧可用后生成，并使用独立的最多 5 路 Prompt 池。

`H3参考素材.json` 必须使用当前 schema，记录项目画幅、H3 Profile、期望宽高、`storySegmentId`、`sceneId`、是否要求场景设计、场景引用清单、场景引用文件哈希、每张场景图 SHA-256、分镜文案、整体视觉风格、当前 Storyboard 指针与图片、角色引用清单与图片、当前分镜计划的输入哈希，以及前镜 Job ID 与尾帧 SHA-256。任一 Prompt 输入、项目画幅、场景引用文件、场景图或前镜尾帧哈希变化，或分镜计划中的场景/依赖关系变化时，旧 Prompt 和当前结果都必须移入历史版本并自动失效，重新生成 Prompt 与视频；前镜失败时，后镜报告 `blocked-by-dependency`，不得退回独立生成或进入最终合并。

豆包提示词生成和 H3 视频生成分别由独立的外层任务池调度；两池各自读取 `GENERATION_MAX_CONCURRENCY`，可同时各运行到该上限，不合并计算。豆包请求使用非流式完整响应，单次等待上限为 420 秒；H3 视频任务异步提交后持续轮询到最终状态。H3 任务使用稳定 UUID 幂等并支持恢复。只做技术验收，不因主观评分自动重生视频。

并发 worker 写共享状态时必须串行持久化；原子写临时文件名至少包含进程 PID 和随机 UUID，不得只用 PID，以免同一进程内多个分镜抢占同一个 `.tmp` 文件。后续批次跳过 `当前视频.json` 已为 `succeeded` 的分镜，只补齐未完成项目。

参考音频始终以原始完整文件上传，不裁剪、不截断；即使参考音频长于 15 秒也原样提交。只有 `duration_seconds` 必须是 3–15 秒整数，并按 `min(15, floor(完整时间线秒数))` 计算。

## P9 验收与定向重做

### 对白硬验收

全部 H3 分镜成功后，必须在合片前逐片段提取 16kHz 单声道 WAV，并使用火山录音文件极速版验证对白；不得改用本地 ASR 作为发布门禁。项目 `.codex/.env` 使用 `VOLCENGINE_ASR_API_KEY` 或 `DOUBAO_ASR_API_KEY`；已配置同账号语音权限时可复用 `DOUBAO_TTS_API_KEY`。

```bash
node <skill>/scripts/音频/验收H3对白.mjs --project <项目目录>
```

脚本默认读取 `配音/角色对白计划.json`，不存在时读取 `配音/语音任务.json` 或项目根目录 `语音任务.json`；也可显式传入 `--plan`。首轮识别不匹配时，自动再识别两次并以多数共识判定。必须满足：

- 计划对白逐句完整，没有漏字、改字、重复或额外人声；
- 无计划对白的片段不得识别出人声；
- 报告 `成片/对白验收-火山ASR.json` 的 `summary.verdict` 必须为 `pass`。

未通过时只处理受影响分镜。对白未说完时先在 3–15 秒限制内增加时长或重分配句间窗口；近音、串词或重复时修正对白发音/节拍约束后重生。只有字级时间能证明额外声音与计划对白完全分离时，才允许静音或截止额外部分；必须保留 H3 原始版和处理记录并重新验收。

### 三帧视觉硬验收

对每个当前 H3 分镜抽取首、中、尾三帧：

```bash
node <skill>/scripts/视频/验收H3视觉.mjs --project <项目目录>
```

必须实际查看脚本输出的 `三帧总览.jpg`，检查无可读文字、无 Storyboard 箭头/批注/编号/分格，色彩和整体风格统一，角色身份稳定，场景干净真实。检查后记录结论：

```bash
node <skill>/scripts/视频/验收H3视觉.mjs --project <项目目录> --record pass --reviewer codex --checks no-readable-text,no-storyboard-marks,style-consistent,character-consistent,clean-realistic-scenes,scene-reference-consistent,cross-shot-continuity
```

三帧验收同时校验 `storySegmentId`、`sceneId`、`场景参考图.json` 及连续 clip 的 `tail-frame` 依赖。必须把同一故事场景的所有分镜与同一组场景设计图比较，并直接比较每个连续对的前镜尾帧与后镜首帧。任一分镜或连续对失败时使用 `--record fail --issues "<问题>"`，只重生受影响的依赖链，然后重新抽帧。分镜视频在抽帧后变更会使报告哈希过期，必须重新验收。

## P10 安全合片与交付

只有对白与三帧视觉两个报告均为 `pass` 且每个源视频 SHA-256 仍匹配时，才能运行 `scripts/视频/合并H3分镜视频.mjs`。脚本先拒绝任何与项目原生 Profile 宽高不一致的源视频，再按该 Profile 统一为 30fps、H.264；9:16 项目必须始终保持 480×864，不得在合片阶段转成横屏。所有音轨均为 AAC 32kHz 双声道时原样复制音频数据包，否则统一规范化后再合并。

合并固定使用 concat demuxer，不得使用会重组时间线的单条 concat filter。发布前必须完整解码视音频，并比对标准化分镜和合并成片的 PCM SHA-256；不一致时停止且不替换当前成片。只有全部检查通过后才原子发布 `成片/完整视频.mp4`、`当前完整视频.json` 和 `安全合片验收.json`；旧成片移入 `成片/历史版本/`，不覆盖丢失。
