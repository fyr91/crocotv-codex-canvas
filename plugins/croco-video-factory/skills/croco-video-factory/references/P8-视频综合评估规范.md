# P8 视频综合评估规范

## 边界

P8 每个正式 Video 生成后，由当前 Codex/Skill 本体直接查看真实视频并完成一次统一综合评估。默认不调用外部视频理解模型，不使用脚本判断视频内容；只有用户明确指定外部模型时才外调。FFprobe 等脚本只负责读取实际时长、编码和可解码性。

综合评估既检查视频是否忠实实现 P2 剧本、P4 导演规划和 P6 生成片段，也检查实际视听结果的连续性与技术质量。它不美化 Prompt、不重新导演、不添加剧情，也不直接修改 P2、P4 或 P6 正文。

## 输入与评估层级

读取实际 Video、`actualDurationSeconds`、P2 锁定剧本片段、P4 导演总纲与文字分镜、P6 Prompt/有序引用/`generationSegmentId`/目标时长，以及相邻片段在当前 `shotId` 内承担的内容。

先评估单个 `generationSegmentId`，再聚合同一 `shotId` 的全部片段；已有相邻分镜时补充检查跨 `shotId` 的必要连续性。不得只凭首/中/尾帧代替真实时间轴。看不清或无法确认的维度记为 `uncertain`，不得猜测通过。

## 统一评估维度

| 维度 | 必须检查 |
|---|---|
| 剧情与信息覆盖 | 计划事件、知识信息、关键画面和必须出现内容是否完整呈现 |
| 顺序与因果 | 事件、动作、反应和信息揭示顺序是否正确，有无重复、遗漏或错误跳跃 |
| 角色与状态 | 身份、数量、形象、服装/Variation、情绪、视线、姿态和状态变化是否正确 |
| 场景、空间与道具 | 场景/时间、空间关系、关键道具、交互对象及其前后状态是否正确 |
| 动作与表演 | 动作是否自然完成，人物交互、反应、情绪和表演重点是否符合分镜 |
| 导演与摄影实现 | 景别、机位、构图、视觉重点、景深、运镜、转场和镜头意图是否实现 |
| 节奏与时长承载 | 内容是否在实际时长内完整展开，有无过快、截断、拖沓或无效停留 |
| 人物/画面/环境动效 | 人物动效、环境变化、物理运动、气氛效果及方向/强度是否符合规划 |
| 声音实现 | 仅对实际视频中存在且 P4/P6 明确规划的对白、旁白、音乐、环境音和音效检查有无、时序、对应关系与明显质量问题；未进入当前生成链的正式声音不得判缺失 |
| 连续性与片段衔接 | 同一分镜多个片段及必要的跨分镜衔接是否保持角色、场景、道具、动作方向和时间逻辑；是否在场景切换或不连续边界合理拆分 |
| 视觉与音频技术质量 | 畸变、闪烁、穿模、漂移、跳变、冻结、乱码/非授权文字、压缩破损、明显噪声、爆音或音画失配是否影响使用 |
| 禁止内容与额外偏差 | 是否出现未授权角色、剧情、物体、Logo、水印、文字或与规划冲突的内容 |

## 证据与总评

每个维度记录 `pass`、`minor`、`fail` 或 `uncertain`，并附实际时间码、预期内容、观察结果、严重度和问题归因。没有时间证据的主观判断不得触发结构回流。

最终只给一个总评：

- `pass`：无阻断问题；允许存在不影响使用的 `minor`，但必须记录。
- `regenerate`：P2/P4/P6 规划和时长承载合理，问题来自本次生成偏差或技术质量；保持 P6 不变，只重生成当前片段。
- `revise-p6`：上游规划正确，但当前片段的目标时长、生成片段拆分或承载范围不合理。
- `blocked-upstream`：必须改变 P2 剧本或 P4 分镜规划才能解决；停止自动回流并请用户决策。
- `needs-review`：关键画面/声音无法可靠观察，或证据不足以安全归因；不得自动判定通过。

若同时存在多个问题，按 `blocked-upstream` → `needs-review` → `revise-p6` → `regenerate` → `pass` 的优先级给出唯一总评，同时保留各问题的独立归因。

## P6 回流限制

`revise-p6` 只允许：在 15 秒上限内延长当前片段、在同一 `shotId` 下拆分 `generationSegmentId`，或增加承载同一规划内容的相邻延续片段。拆分优先级为：场景切换处 → 本来不连续的画面/动作边界 → 其他自然停顿。优先使用 `independent` 或 `soft-continuity`；只有没有安全断点时才使用 `tail-frame`。

不得改变 P2 剧本文字、P4 `shotId`、分镜目的、事件顺序、导演判断或镜头规划。纯生成瑕疵不得触发 `revise-p6`。

## 评估记录

保存 `shotId`、`generationSegmentId`、Video 标识/哈希、P2/P4/P6 输入哈希、目标/实际时长、各维度结论、时间证据、问题归因、唯一总评、处理动作和评估时间。Canvas 使用既有 Comment/metadata 保存这份非模型评估记录；Skill 原生保存 Markdown/JSON。评估本身不是 Text Config Result，也不创建虚假的验证节点。
