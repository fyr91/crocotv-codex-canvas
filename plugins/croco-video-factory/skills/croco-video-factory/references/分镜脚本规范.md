# 分镜脚本规范

## 核心原则

先守住 `视频脚本.md` 的最终内容和 `内容大纲.md` 的知识目的，再安排分镜分组、空间、角色和镜头。不得新增、删除或改写事实、台词、用户明确要求的画面文字和事件顺序；需要改变内容时返回内容策划阶段。画面文字默认无，自动策划内容不得转化为画面文字。

分镜组是连续 3–15 秒的制作单元，可包含多个按时间顺序排列的画格；画格用于呈现关键动作或状态节点，不等同于固定镜头数量。分镜开始前必须先按[故事场景设计规范](故事场景设计规范.md)完成故事分组和固定场景设计图。Storyboard 整张画布、每个画格内部构图和角色安全区都必须按 `分镜计划.json.aspectRatio` 原生设计；9:16 项目使用竖向 Storyboard 结构，不得生成横屏 Storyboard 后再裁切、补边或转换。

## 1. 脚本覆盖

设计镜头前，逐节拍确认以下内容分别由哪个分镜组落实：

- 知识目的与必须看懂的可见证据。
- 视觉事件、角色动作和关键反应。
- Narration、Dialogue、画面文字和关键音效。

只有纯理解背景且不需要直接呈现的内容可以不进入画格。不得因追求漂亮构图而遗漏解释、证据、反应或脚本文字，也不得无理由重复同一动作或信息。

## 2. 分镜目的

每个分镜组先用一句话确定：

1. 观众此刻必须注意并理解什么。
2. 本组结束时，知识、信息、动作或角色状态发生什么变化。
3. 为什么需要在这里建立新分组或切换画格，而不是留在前一个画面。

先确定分镜目的，之后再选择景别、角度、构图和运镜。镜头语言必须服务知识表达、注意力或状态变化，不能只为每段内容添加摄影形容词。

## 3. 拆分与合并

以脚本中的时长为参考，根据知识密度、动作变化、空间变化和镜头变化确定最终分组：

- 一个分镜组无法清楚承载知识点、动作顺序、空间关系或对白后的关键反应时拆分。
- 新画格带来新的注意重点、可见证据、动作状态、视角或叙事作用时保留切换。
- 相邻画格没有增加新信息或状态变化时合并，避免只换角度的重复画面。
- 拆分与合并只能调整视觉承载方式，不得重排脚本事件或改变因果关系。

## 4. 分镜记录

每个分镜组记录：

- 时间码和参考时长。
- `storySegmentId`、`sceneId` 及场景设计图绑定。
- 知识目的与分镜目的。
- 场景、角色及其绑定素材。
- 起始状态、按顺序排列的动作节点和结束状态。
- 角色位置、动作、表情及必要反应。
- 景别、角度、构图、运镜和转场。
- 严格分开的 Narration 与 Dialogue，以及对应角色。
- 用户明确要求的画面文字（没有则写“无”）、关键音效和需要明确呈现的可见证据。

## 5. 空间与角色连续性

相邻画格必须核对角色位置、朝向、视线、屏幕运动方向、进出路线、双手与持物、服装状态、场景锚点和光线方向。上一画格的结束状态必须能够直接承接下一画格的起始状态；不得提前展示后续才发生的发现、决定、持物变化或知识揭示。

分镜组之间必须在 `分镜计划.json` 中显式记录连续性关系，每个非合成分镜还必须记录 `storySegmentId`、`sceneId` 和 `sceneDesignRequired: true`：

- `independent`：场景切换、普通硬切或无需继承具体画面的镜头，可并行生成。
- `soft-continuity`：复用同一 `sceneId` 但属于不同 `storySegmentId` 的时间跳跃或独立镜头；必须继续使用同一组场景设计图，允许重新构图，不等待前镜视频。
- `tail-frame`：动作、运镜、变形或同一连续镜头跨分镜组延续；必须填写更早的 `dependsOnShotId`、选择原因 `reason` 和需继承的 `inherit`，并等待前镜视频尾帧。

```json
"continuity": {
  "type": "tail-frame",
  "dependsOnShotId": 7,
  "reason": "同一仰视镜头继续拉回地面",
  "inherit": ["composition", "characterPose", "cameraDirection", "lighting"]
}
```

因 H3 时长限制而拆开的同一段故事，如果相邻分镜的 `storySegmentId` 和 `sceneId` 都相同，后一分镜必须选择 `tail-frame` 并直接依赖前一分镜；不得降级为 `soft-continuity` 或 `independent`。只有故事、场景或时间确实断开时才避免硬依赖。

生成 Storyboard 时先按 `场景参考图.json` 顺序上传场景设计图，再按 `角色参考图.json` 顺序上传角色设计图。`分镜画面提示词.md` 必须按该实际上传顺序绑定每张 Reference：场景 Reference 锁定空间、灯光、材质、家具和道具锚点；角色 Reference 锁定角色身份、物种/类型、年龄、体型、服装和可识别特征。每个画格都必须沿用该绑定，不得在角色和场景之间转移属性。

参考图只锁定身份、物种/类型、年龄、体型、服装和可识别特征，不复制角色表排版、三视图、背景或媒介风格。

## 6. 生成 `分镜画面提示词.md`

产物定位为展示连续镜头的纯分镜表。每个文件依次写入：

1. `Storyboard基础提示词.md` 的固定英文文本。
2. 分镜组信息：编号、时间码、参考时长、知识目的、分镜目的、场景、整体风格和阅读顺序。
   同时写明项目画幅与原生画布约束，例如 `9:16 portrait storyboard sheet; every panel composes natively for a 9:16 video frame`。
3. `Reference 1...N`：按实际上传顺序先绑定场景设计图，再绑定角色身份和不可改变特征。
4. `Panel 1...N`：按叙事顺序逐格描述镜头。
5. 全局约束：角色与场景不变量、必须准确呈现的画面文字及禁止漂移项。

每个 Panel 必须包含：

- 画格编号和对应时间段。
- 本格镜头目的，以及观众必须看到的知识或信息。
- 景别、角度、构图、运镜、焦段意图和与上一格的转场关系。
- 场景、出场角色、动作、表情、视线、持物和关键可见证据。
- Narration、Dialogue 和画面文字的边界；它们作为彩色技术批注，不改变黑白画格主体。
- 画格结束状态，以及下一格必须继承的连续性锚点。

多画格按照从左到右、从上到下的顺序阅读。根据时长、叙事密度、动作变化和镜头变化自动决定画格数量；每格只呈现一个可同时成立的关键时刻。使用足够画格覆盖必要节拍，但不得把多个连续动作硬塞进同一格。信息过密或单张无法清楚阅读时，拆成多张分镜表并连续编号，不得缩小画格强行容纳。

不得调用外部大语言模型二次改写 Storyboard 提示词。完成后核对固定英文开头、画格顺序、画格结束状态、全部参考图身份绑定和全局约束，再直接交给 Nano Banana Lite。

## 7. 生成前自检

- 脚本中的知识点、视觉事件、旁白、对白和画面文字均有明确落点。
- 每个分镜组都有清楚的分镜目的，切换画格有信息或状态理由。
- 动作节点保持原始顺序，起始状态与结束状态能够连续承接。
- 镜头语言服务知识表达，没有遮住必须呈现的证据或反应。
- 场景设计图已验收，每个非合成分镜已绑定 `storySegmentId`、`sceneId` 和 `场景参考图.json`。
- 同一故事场景的相邻分镜已建立 `tail-frame` 直接依赖，角色身份、外形、持物和空间关系没有漂移。
- 固定英文开头、多画格顺序、整体风格和全部参考图身份绑定均已写入。
