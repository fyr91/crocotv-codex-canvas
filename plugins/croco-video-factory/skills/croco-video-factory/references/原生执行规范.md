# Skill 原生原子能力执行规范

## 边界

本文件只说明 `Projects/`、Markdown/JSON、媒体、子 Skill、Provider 和脚本如何执行[唯一 P1–P8 流程](执行后端选择规范.md)，不是另一套流程。原生后端不模拟 Canvas 节点；项目文件与运行状态是唯一事实来源。

运行捆绑脚本前，把工作目录设为 CrocoTV 仓库根目录。脚本从 `CROCO_ENV_FILE`（默认 `.codex/.env`）读取环境，只执行当前阶段，不跳过共同 Gate。

## 原生状态与版本

- P1 创建唯一 `Projects/YYYYMMDDTHHmmss-主题/` 项目。
- 每个阶段保存当前 Markdown/JSON、输入快照、内容 SHA-256、Prompt `templateKey/templateVersion`、运行状态和历史版本；更新 current pointer 前先验证目标存在。
- 模型输出保留独立版本，人工反馈作为新输入重新调用负责模型；不得覆写旧模型 Result 冒充重跑。
- 研究动作不写进度文件；被模型消费的 Claim/source、引用与结论写入权威阶段文件。

## 原子能力映射

| 能力 | 现有实现 | P1–P8 用法 |
|---|---|---|

| 角色资源 | `pull-latest-characters`、`角色与时长.mjs` | P1/P3 按需同步与解析；不替用户选角色 |
| 文字模型 | GPT（Codex Skill 本体）/Provider + 版本化 System Prompt | GPT 执行 Skill 编排、P2 调研 Gate 与共享矩阵中标注的本体任务；只在矩阵指定时外调 Gemini、GLM、豆包或其他模型 |
| 四视图 | `生成NPC四视图.mjs`、`记录图像验收.mjs` | P3 默认 Nano Banana Lite；用户指定 GPT 时先走内置 `imagegen`，超时/失败再用脚本外调 GPT Image 02 |
| 场景综合图 | `生成场景设计图.mjs`、`记录场景设计验收.mjs` | P3 默认 Nano Banana Lite；用户指定 GPT 时使用同一 GPT 路由 |
| Storyboard | `生成分镜图.mjs` + Storyboard 模板/验收 | P5 标准模式外调 GPT Image 02；`--fast` 快速模式使用 Nano Banana Lite |
| H3 Prompt | Ref2VA 通用 System Prompt、`生成H3提示词.mjs` | P6 按预估生成时长用豆包生成正式 Prompt；不运行 Prompt validator |
| H3 视频 | `生成H3分镜视频.mjs`、`h3-client.mjs` | P6 后直接生成 P8 正式分镜片段，并媒体探测实际时长 |
| 视频综合评估 | Codex/Skill 本体 + `P8-视频综合评估规范.md` | Codex 直接查看真实 Video 并结合 P2/P4/P6 做统一综合评估；不使用视频理解脚本，默认不调用外部模型 |
| Speech | `character-speaking` | 后续正式 Speech 阶段启用时按需调用 |
| 专项验收/合片 | ASR、人工追加复核、合并 scripts | 保留给 P8 之后按需使用；不重复 P8 默认综合评估 |

## 执行要点

- P2 依次运行 Gemini 主题/大纲、Codex 研究/Claim-source/source verification 与事实 Gate、Gemini 剧本、GLM 校定；Codex Gate 未通过不得调用剧本生成，用户确认前不得进入 P3。
- P3 只有缺新资产时调用 Gemini 综合设计；图像生成默认 Nano Banana Lite，不使用普通 Nano Banana；用户指定 GPT 时按[图像模型路由](图像模型路由规范.md)执行。四视图和场景综合图继续使用当前最多五次、85 分/关键错误/best-effort 规则。
- P4 由 Gemini 生成全片导演总纲和正式文字分镜，过长才按批次；GLM 只在全片完成后总审一次。无需先生成音频，直接按对白/旁白文字、非并行动作、前后留白和向上取整记录 3–15 秒预估生成时长。受影响分镜重跑 Gemini，不让执行层直接改正文。
- P5 确定性组装固定 Storyboard Prompt，不调用通用 LLM 二次改写。标准模式外调 GPT Image 02；用户明确选择快速模式时改用 Nano Banana Lite。
- P6 使用受管理 Ref2VA 通用 System Prompt。`生成H3提示词.mjs` 必须逐字读取 `references/H3-Ref2VA-System-Prompt.txt` 的完整内容作为唯一 `system` message，不得 trim、拼接、摘要、翻译或在代码中追加隐式系统指令；runtime brief 与媒体引用只放在独立 `user` message。豆包 Seed 2.1 Turbo 直接生成最终六段式 Prompt；脚本按真实文件顺序绑定引用，只做空响应、长度、时长和输入快照等技术检查，不调用外部审核或修订模型。需要片段化时保留 P4 `shotId`，另建 `generationSegmentId`。
- P6 后直接进入 P8，不创建 `Trailer/`、Pre-roll、压缩 Prompt 或 P7 确认。
- P8 消费 P6 锁定 Prompt；依赖链串行、独立链并发，前镜失败则后镜 `blocked-by-dependency`。每段成功后用媒体探测记录 `actualDurationSeconds`，再由 Codex 直接查看真实视频并按综合评估规范对照 P2/P4/P6；不新增视频理解脚本，默认不外调模型。`regenerate` 只重生成当前 P8 片段；`revise-p6` 只在同一 P4 分镜内延长、拆分或增加延续片段，优先从场景切换或不连续画面边界拆分；非必要不拆连续动作，无法避免时才用 `tail-frame`。只重跑受影响 P6/P8 片段及依赖链。

只有当前 Prompt、System Prompt、场景、角色、音频和前镜尾帧哈希都匹配时才复用结果。任何变化将旧 current 移入历史并只重跑受影响依赖链。
