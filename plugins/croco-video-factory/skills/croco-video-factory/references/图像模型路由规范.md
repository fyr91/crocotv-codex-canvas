# 图像生成与修改模型路由规范

## 模型边界

Croco Video Factory 自动流程的 P1–P8 图像链只使用：

- Nano Banana Lite：`google:nano-banana@2-lite`；
- GPT Image 02：`openai:gpt-image@2`。

普通 Nano Banana（`google:4@1`）不属于本自动流程的默认或可选路由，Skill 不得自动选用。这不限制 Canvas runtime 的通用模型目录：所有 runtime 已支持模型均继续保留和显示，用户脱离本流程直接操作 Canvas 时可自由选择。

## 固定默认

| 任务 | 默认路由 | 用户可覆盖项 |
|---|---|---|
| P3 角色四视图、场景综合设定图及其他新图 | Nano Banana Lite | 用户明确指定 GPT 时改走 GPT 路由 |
| P5 Storyboard 标准模式 | 外部 GPT Image 02 | 用户可选“快速模式” |
| P5 Storyboard 快速模式 | Nano Banana Lite | 只由用户明确选择，不由 Auto 自动降级 |
| 已有图片优化、局部/整体修改与迭代 | Nano Banana Lite | 用户明确指定 GPT 时改走 GPT 路由 |

“默认 Nano Banana Lite”不覆盖 Storyboard 的阶段专用默认；P5 标准模式固定优先使用外部 GPT Image 02。

## 用户指定 GPT 时

### Skill 原生后端

1. 加载并使用 Codex 内置 `imagegen` Skill 的 built-in `image_gen` 路径。
2. 首次等待窗口为 120 秒。若在该窗口内获得可用图片，将选定结果复制到项目资源目录，不得只留在 `$CODEX_HOME/generated_images/`。
3. 若 120 秒内未得到可交付结果、内置工具不可用或明确失败，改走 Runware 外部 `openai:gpt-image@2`。已发起的内置任务若无法取消，其迟到结果不得覆盖已锁定外部结果。
4. 保存 `requestedRoute: gpt`、`actualModel`、`fallbackReason`、Prompt/引用快照和输出 SHA-256。

P5 Storyboard 标准模式是明确的外部 GPT Image 02 路由，不先调内置 `imagegen`；这保证 Storyboard 批量生产的模型、元数据和重跑路径稳定。

### Canvas 后端

Canvas 中用户对普通生图/修改任务指定 GPT 时，先执行[Canvas 内置 ImageGen 落图操作](Canvas-ImageGen落图操作规范.md)：内置 `imagegen` 生成后导入本地资源库，再原子创建 Prompt Text → Image 来源连线。该 Image 必须标记为 `sourceKind: imported-generation`，不伪装为 Provider Result。

内置 `imagegen` 首次等待超过 120 秒、不可用/失败，或用户明确指定“在画布上生成”时，改走真实节点链：

```text
Prompt Text + 有序 Reference Image
        ↓
openai:gpt-image@2 Image Config
        ↓ canvas_run_nodes
Image Result
```

P5 Storyboard 标准模式仍默认使用上述 GPT Image 02 节点链；快速 Storyboard、普通默认生图和默认图片修改将 Config 模型替换为 `google:nano-banana@2-lite`。图片修改必须把当前 Image 作为真实 Reference 连接到新 Config，保留旧结果，不直接覆写 Image Result。

## 记录与失效

每次生成或修改记录 `requestedRoute`、`actualModel`、`mode: standard|fast|edit`、Prompt 版本、有序引用和 `inputSnapshot`。模型、模式、Prompt 或任一引用变化都使当前结果失效，重跑时保留历史。
