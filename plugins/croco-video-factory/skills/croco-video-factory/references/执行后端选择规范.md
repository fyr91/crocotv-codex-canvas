# 固定制作流程与执行后端规范

## 权威边界

本文件是阶段顺序、模型职责、共同产物、门禁和失效规则的唯一权威。领域规范只定义阶段如何达标；Canvas MCP 与 Skill 原生文档只映射原子能力，不得复制、增删或重排流程。

- Auto / 互动只改变可选暂停方式。
- 本地 Canvas / Skill 原生只改变执行机制和状态载体。
- 两套后端的能力粒度可以不同，但必须产出相同语义的阶段结果、来源快照和 Gate。

第一轮同时确认生产控制与执行后端。两项未确定前不得询问 Topic、角色或风格，不得创建项目或调用第三方生成。

## P1–P8 唯一阶段定义

| 阶段 | 固定工作 | 固定出口 |
|---|---|---|
| P1 项目需求与创作边界 | 确认 Topic、受众、方向、时长、画幅、正式角色、现有资源、风格偏好、禁区和可补全范围 | 项目简报、角色/Voice/资源索引、硬约束与缺失项；正式角色只能来自用户指定 |
| P2 主题、大纲、事实 Gate 与剧本锁定 | Gemini 主题分析/大纲 → 定向研究与 Claim/source 映射 → DeepSeek V4 Pro 事实 Gate → Gemini 剧本初稿 → GLM 表达校定/去 AI 化 | 当前最终剧本、事实 Gate、版本哈希和 `approvalSnapshot`；Auto/互动都强制用户确认 |
| P3 可生产角色与剧本场景资产 | 从锁定剧本提取需求；复用已有角色；按需设计角色总体设定、Variation、声音身份、四视图、剧本级场景/道具和场景综合设定图；生图默认 Nano Banana Lite，用户可明确指定 GPT 路由 | 稳定角色/Variation/Voice 引用、已验收四视图与场景综合图；不拆分镜 |
| P4 导演总纲与正式文字分镜 | Gemini 一次阶段任务形成全片导演规则并按 Storyboard Unit 拆分/设计文字分镜；无需先生成正式音频，按对白/旁白预估、动作、前后留白和向上取整得到 3–15 秒预估生成时长；GLM 全片完成后做一次跨分镜总审 | 锁定导演总纲、正式 `shotId`、逐分镜文字设计、预估生成时长、连续性和引用关系；不生成 Storyboard |
| P5 Storyboard | 固定模板确定性组装 Prompt；标准模式调用外部 GPT Image 02，用户选择快速模式时调用 Nano Banana Lite；按 Rubric 验收 | 当前 Storyboard、生成模式/实际模型、Prompt/引用快照和验收记录 |
| P6 正式 H3 Prompt | 豆包 Seed 2.1 Turbo 使用统一 Ref2VA System Prompt，按 P4 的预估生成时长形成每个正式分镜的生成片段 Prompt；Result 直接锁定，不调用内容 validator 或外部审核/修订模型 | 每个 `shotId` 下的一个或多个 `generationSegmentId`、目标生成时长、锁定豆包 Result、有序素材、System Prompt/输入哈希 |
| P8 正式 H3 分镜视频与综合评估闭环 | P6 后直接按锁定 Prompt 和依赖图执行 MiniMax H3；每个结果记录实测时长，由 Codex 对真实视频做统一综合评估；按问题归因重生成当前片段、回 P6 拆分/扩展，或停止上报上游冲突 | 当前正式 Video、实测时长、尾帧、任务/输入快照和综合评估记录；总评通过后停止 |

## 关键模型调用矩阵

| 阶段 | Skill 本体（GPT） | Script / 规则 | 默认外部模型 |
|---|---|---|---|
| P1 | 收集需求、澄清边界、结构化项目简报 | 完整性、资源索引与状态校验 | 无 |
| P2 | 定向研究编排、Claim/source 映射、回流与版本锁定 | 哈希、Gate 状态和结构校验 | Gemini：主题+大纲一次、剧本一次；DeepSeek V4 Pro：事实 Gate 一次；GLM：后置校定一次 |
| P3 | 从剧本提取需求、判断复用、绑定资产和组装模板 | 资产 schema、图片 Rubric 和版本校验 | 仅缺新资产时 Gemini 一次综合设计；生图默认 Nano Banana Lite，用户指定时使用 GPT 路由 |
| P4 | 组织剧本/资产输入、建立 `shotId`、管理审核回流和预估生成时长 | ID、资产引用、时长取整和连续性结构校验 | Gemini 一次阶段任务；GLM 一次跨分镜总审 |
| P5 | 按锁定文字分镜组装 Storyboard Prompt 和验收记录 | 固定模板、引用顺序和 Rubric | 标准模式为外部 GPT Image 02；快速模式为 Nano Banana Lite；不默认调用外部通用文字模型 |
| P6 | 汇总 runtime brief、引用与统一 Ref2VA System Prompt | 空响应、长度、来源和输入快照技术检查 | 豆包 Seed 2.1 Turbo 生成最终 Prompt；不调用审核模型 |
| P8 | 编排 H3、管理依赖、直接理解真实视频并完成统一综合评估，按问题归因执行重生成、回流 P6 或停止上报 | FFprobe 实测时长、输入快照、依赖和状态校验；不使用视频理解脚本 | MiniMax H3 生成；默认不调用外部视频理解模型，用户明确指定时才调用其指定模型 |

本表的 **GPT** 指当前执行 Croco Video Factory Skill 的 Codex 模型，不是额外 Provider API 调用。Skill 本体完成的理解、编排、提取、组织、回流决策和交付统一记为 GPT；纯 schema、哈希、排序、状态和 validator 记为 Script / 规则，不冒充模型审核。Canvas 后端中，只有右栏外部模型建立 Provider Text/Image/Video Config 生成链；GPT 通过 MCP 原子能力组织输入、调度运行和保存非模型 Result 的确定性产物。

DeepSeek V4 Pro 在 P1–P8 中只负责 P2 事实 Gate，不参与通用策划、剧本校定或 P4 审核。DeepSeek V4 Flash GA 正式版（`deepseek-v4-flash-ga-260731`）不再用于已取消的 P7；正式 Speech 阶段启用时只负责逐字保真的语气分段，再交给 Seed-TTS。P8 默认由当前 Codex/Skill 本体直接理解真实视频，不固定外部模型；只有用户明确指定时才调用外部视频理解模型。

## Gate 与回流

- P2 是所有模式的强制人工 Gate。确认前不得运行下游正式生成；P6 后不再插入 P7 Pre-roll Gate。
- 其他阶段沿用当前政策：互动模式可暂停；Auto 模式在契约校验通过后继续。图片/Storyboard 的 85 分、关键错误、最多五次和 best-effort 规则保持现状。
- P2 只在大纲 Claim 或限定条件变化时重跑事实 Gate。纯表达反馈只重跑后置 GLM；剧本偏离大纲时重跑 Gemini 剧本，不用 GLM 擅自修事实结构。
- P8 综合评估为 `regenerate` 时只重生成当前片段；为 `revise-p6` 时保持 P4 `shotId`、剧本覆盖、导演意图和事件顺序不变，优先在场景切换或不连续画面/动作边界拆成独立生成片段，只有没有可用断点时才拆连续片段并建立 `tail-frame`；为 `blocked-upstream` 时停止并上报，不得借 P6 回流偷改上游。
- 任一内容、资源、顺序、System Prompt、场景或前镜尾帧哈希变化时，只使受影响结果和依赖链失效。

## 共同状态契约

生成结果记录 `inputSnapshot`；用户确认记录 `approvalSnapshot`；Prompt 记录稳定 `templateKey`、`templateVersion` 和内容 SHA-256。模型 Result 不得被执行层直接改写；人工反馈作为新输入重跑对应 Config/模型调用。

研究、验证和状态查询是动作，不建立虚假进度产物；但模型消费的研究结论、来源和审核输入必须成为可追溯的阶段输入。
