# P3 剧本场景与道具生产设计规范

## 边界

从 P2 锁定剧本提取剧本级大场景和道具，不按 Storyboard Unit 拆场景。P3 只固定后续可复用的空间、光线、色彩、材质、道具与覆盖方向；不决定正式镜头或连续性依赖。

## 场景计划

`场景/场景计划.json` 使用项目原生 `aspectRatio`。每个场景记录：

- 稳定 `sceneId`、名称、出现的 `beatIds`/剧本片段和空间功能；
- 建筑/空间结构、尺度、出入口、前中后景与固定地标；
- 主光方向、时间、色彩、材质和气氛边界；
- 大道具、小道具、角色交互点、相对位置与不可漂移锚点；
- 主覆盖方向、必要反向/侧向覆盖和禁止暴露区域。

同一场景发生时间跳跃时保留 `sceneId`，通过状态/光线变体记录；空间结构发生实质变化时创建新场景或明确 Variation。

## 每场景综合设定图

默认每个剧本场景生成一张综合设定图，在同一张图中同时呈现：主空间大图、必要反向/侧向覆盖、固定道具和材质/光线关系。使用[场景综合设定图基础提示词](场景综合设定图基础提示词.md)。复杂场景仍先尝试一张综合图；只有单图无法保持空间可读性时才暂停请求用户决定是否拆分。

综合图是最终成片质感的空场景生产参考，不是 Storyboard。默认不出现角色，不得有文字、Logo、箭头、批注、分格编号或水印；必须按项目画幅原生构图，不能先横屏后裁竖屏。

原生生成：

```bash
node <skill>/scripts/策划/生成场景设计图.mjs --view-dir <场景目录>
node <skill>/scripts/策划/记录场景设计验收.mjs --view-dir <场景目录> --attempt 1 --record pass --reviewer codex --checks spatial-layout,lighting-palette,materials-props,camera-coverage,clean-no-text
```

继续沿用每项最多五次和 current pointer。只有当前验收为 `pass` 的综合图可进入 P4/P5/P6/P8。

## 验收

必须检查：

- 各覆盖方向属于同一空间，结构、出入口与相对位置自洽；
- 主光方向、时间、色彩和材质一致；
- 家具、大小道具和交互锚点位置稳定；
- 足以覆盖剧本需求且没有与剧本冲突的空间；
- 画幅原生、默认空场、无文字/Logo/箭头/批注/水印。

P4 正式文字分镜再为每个 `shotId` 绑定一个或多个有序 `sceneIds`，并建立 `independent / soft-continuity / tail-frame` 关系。一个分镜可以跨不同场景。
